# Runtime revisions

> **Carried from the old platform.** This document was written before the rewrite and is kept as it was, except for
> its links. Paths into code, runs and other docs (`packages/`, `mechanics/`, `stories/`, `examples/`, `docs/`) that do
> not exist on this branch point at the tag [`v0-final`](https://github.com/florianpirchner/swarmtales/tree/v0-final) of this repository.

The runtime revision (`RUNTIME_REVISION` in `packages/kernel/src/revision.ts`) changes only when the runtime
changes how a run plays: when a resident is woken, what stays in its context, how tool notices and tool answers
arrive. It does not change with every commit. Runs of one revision are comparable; a comparison that mixes
revisions says so.

- Every run writes its revision into the genesis of its chain (`runtime`), into `000-run.json` (`runtime`) and
  into the header of its `REPORT.md`; `swt log verify` shows it.
- **A run that names no revision is revision 1.** Run data is never rewritten afterwards: `events.jsonl` is
  signed, and the run's private key is gone.
- A recorded run folder carries the revision in its name when it is not 1: `chess-02a-045-default-g4-s41-r2`.
  Folders without a suffix are r1.
- Every runs index has a `Runtime` column.
- The git tag `runtime-rN` (set by hand: the cloud container cannot push tags) marks the commit a revision starts at (`runtime-r1` the last commit of revision 1).
  `git merge-base --is-ancestor <run commit> runtime-r2` tells on which side a run lies; `git checkout
  runtime-r1` brings the old runtime back to replay an old run exactly.
- A PR that changes how a run plays raises the revision, adds a row here and sets the tag at its merge commit.

| Revision | From | What changed | Effect seen |
|---|---|---|---|
| r1 | every run up to commit `b6f991c` (tag `runtime-r1`), including the runs of the older arena runtime | the baseline | - |
| r2 | commit `4271ceb` (PR #145, tag `runtime-r2`) | A tool answer may end the caller's turn (`ToolSuccess.endsTurn`): its answer alone wakes no new step, so no model call is spent on answering "end your turn". Set by chess (`playMove`, `resign`), Hold'em (an action after which another seat is to act) and liar's dice (a bid or call after which another seat is to act). Under r1 the seat was woken during the opponent's move to answer its own tool result: 114-133 extra requests per four-game chess match, about 15% of the cost (Opus commented on its move, Sonnet called `viewBoard` and put one more board into its context). | chess: about 15% fewer requests per match (to be measured in the r2 baseline run) |
| r3 | the rewritten kernel (branch `rewrite/develop`, milestone M1; the tag `runtime-r3` is set when `main` moves) | The new kernel with the `turns` scheduler: ticks from 0, one log of envelopes, the event names of the kernel. It plays tic-tac-toe teams as r2 did (nine oracle files at level 3). Added in M2 without a new revision, because none changes when a resident is woken or what it is shown: records of declared sources (`Kernel.record`, `Activation.record`), limits given from outside (`KernelPorts.limits`), redaction of the end detail through `KernelPorts.redact` | none on play |
| r4 | issues M4-01 and M4-02 of milestone M4 (branch `rewrite/develop`, decision A34; the tag `runtime-r4` is set by hand at the merge commit of M4-02, and no run is recorded between the two merges) | No payload holds a log position. M4-01, the mechanic `decisions`: `decision_settled.amendments[]` names an amendment by `n`, its number within its decision from 1, where it held `seq`, the log position of the amending call; `decision_amended` carries the same `n`. M4-02, the Directors: a firing is named by `n`, its number among the firings of its Director from 1 (counted in the slice of the plugin `directors`), where it held `seq`, the log position of the event that fired: in the reply of `take`, in the Director's context (`ctx.firings`, which a Director's `input` may print into its model's prompt) and in the record `asked { firings }`. The line that fired is found from the log: the line of the firing's tick with its event type and payload (`findFirings` of `@swarmtales/runlog`). Not changed: when a resident is woken and what a resident is shown; the reply of `amendDecision` and every prompt text are as they were | The played log of a game with an amended decision changes in these two payloads, that of a game with a Director that is asked in the reply of `take` and in `asked`; a log without an amendment and without a Director is byte-equal to its r3 log. No tabletop game has a decision, so no oracle file and no log of the M2 gate changes: r4 runs of those games stay comparable with their r3 runs. A resumed run writes the same payloads as the straight run, and a Director is asked the same question after a resume: the resumed log equals the straight log after the marker line is taken out and the envelope fields `seq`, `causedBy` and `basis` behind it are moved back by one. A snapshot of r3 with a Director does not load (the slice of `directors` is version 2) |
| r5 | issue M4-68 of milestone M4 (branch `rewrite/develop`, decision A46; the tag `runtime-r5` is set by hand at its merge commit) | The cost meter of a live run reserves the cost of its dearest answer so far (P472): the limit `models.budget` is breached as soon as one more answer of that cost would reach the cap, so no request is sent that the dearest answer says would pass it, and the run ends at that tick. Under r4 it was breached only at the cap, and the request that took the sum over it was sent (`hello-game-002`: 0.00133 USD against 0.001). The reason of `limit_reached` writes the money in full (up to nine decimals: "cost 0.000815355 USD and the dearest answer so far (0.0002021 USD) reach the cap of 0.001 USD") where r4 rounded it to two ("cost 0.00 USD reached the cap of 0.00 USD"). A cap can still be passed by one answer dearer than every one before it, and by requests sent at the same time (a scheduler that runs several actors at once). `swt replay` meters the cap of the manifest again by the rule of the run's revision, so an r4 run that ended at its cap replays equal (P471). Not changed: a run without a cap (every fake run, every oracle test), when a resident is woken and what it is shown | Only a live run that comes near its cap plays otherwise: it ends earlier, under its cap. On the logged case the r5 meter would have sent 12 of the 14 requests and spent 0.000815 USD of the cap 0.001. Fake runs and oracle files are byte-equal to r4 |
